
	✅ 1. Reverse a String
	🔹 Normal Approach

	Convert string to char[]

	Loop from end to start

	Build new string

	String str = "hello";
	String rev = "";

	for (int i = str.length() - 1; i >= 0; i--) {
		rev += str.charAt(i);
	}
	System.out.println(rev);


	⏱ Time: O(n)
	📦 Space: O(n)

	⚠️ Interview note: String concatenation is costly.

	🔹 Optimized Approach

	Use StringBuilder (mutable).

	String str = "hello";
	String reversed = new StringBuilder(str).reverse().toString();
	System.out.println(reversed);


	⏱ Time: O(n)
	📦 Space: O(n)

	✅ 2. Check if a String is Palindrome
	🔹 Normal Approach

	Reverse string

	Compare original & reversed

	String str = "madam";
	String rev = new StringBuilder(str).reverse().toString();

	if (str.equals(rev)) {
		System.out.println("Palindrome");
	}

	🔹 Optimized Approach (Two Pointer)

	Compare start & end characters

	String str = "madam";
	int left = 0, right = str.length() - 1;
	boolean isPalindrome = true;

	while (left < right) {
		if (str.charAt(left) != str.charAt(right)) {
			isPalindrome = false;
			break;
		}
		left++;
		right--;
	}
	System.out.println(isPalindrome);


	⏱ Time: O(n)
	📦 Space: O(1)

	✅ 6. Check if Two Strings Are Anagrams
	🔹 Normal Approach (Sort)
	String s1 = "listen";
	String s2 = "silent";

	char[] a1 = s1.toCharArray();
	char[] a2 = s2.toCharArray();

	Arrays.sort(a1);
	Arrays.sort(a2);

	System.out.println(Arrays.equals(a1, a2));

	🔹 Optimized Approach (Frequency Map)
	String s1 = "listen";
	String s2 = "silent";

	if (s1.length() != s2.length()) {
		System.out.println(false);
		return;
	}

	int[] count = new int[256];

	for (int i = 0; i < s1.length(); i++) {
		count[s1.charAt(i)]++;
		count[s2.charAt(i)]--;
	}

	System.out.println(Arrays.stream(count).allMatch(c -> c == 0));
	
	🧠 Step 0: Create the array
	int[] count = new int[256];


	What JVM does:

	Creates 256 boxes

	Each box has a number (index) and a value

	All values start at 0

	Index : Value
	108   : 0
	105   : 0
	115   : 0
	(all others also 0)


	Nothing added. No math. Just empty boxes.

	🧠 Step 1: First iteration (i = 0)
	char c1 = s1.charAt(0); // 'l'
	char c2 = s2.charAt(0); // 's'


	Now JVM converts characters to numbers automatically:

	'l' → 108
	's' → 115

	Execute this line 👇
	count[c1]++;


	Replace with real numbers:

	count[108] = count[108] + 1;


	Memory becomes:

	Index : Value
	108   : 1

	Execute next line 👇
	count[c2]--;


	Replace with real numbers:

	count[115] = count[115] - 1;


	Memory now:

	Index : Value
	108   : 1
	115   : -1


	👉 Notice:

	No 108 + 115

	Two separate boxes changed
	
	✅ Final Answer (Plain & Correct)

	It only changes the value stored at that index.
	The index itself never changes and indexes are never added together.

	int left = 0, right = arr.length - 1;

	public class ArmstrongNumber {

    public static boolean isArmstrong(int num) {
        int original = num;
        int digits = String.valueOf(num).length();
        int sum = 0;

        while (num > 0) {
            int digit = num % 10;
            sum += Math.pow(digit, digits);
            num /= 10;
        }
        return sum == original;
    }

    public static void main(String[] args) {
        int n = 153;
        System.out.println(isArmstrong(n)); // true
    }
}

	“Calling t1.start() and t2.start() only requests the JVM to schedule the threads. The execution order is not guaranteed. Due to context switching, Thread 1 may acquire the first lock and pause, allowing Thread 2 to acquire the second lock, leading to circular wait and deadlock.”

	Solution 1: Lock Ordering (BEST & MOST ASKED) :
	
	✅ Always acquire locks in the same order
	
	class DeadlockSolution {

		private static final Object LOCK1 = new Object();
		private static final Object LOCK2 = new Object();

		public static void main(String[] args) {

			Thread t1 = new Thread(() -> {
				synchronized (LOCK1) {
					synchronized (LOCK2) {
						System.out.println("Thread 1 executed safely");
					}
				}
			});

			Thread t2 = new Thread(() -> {
				synchronized (LOCK1) {   // same order
					synchronized (LOCK2) {
						System.out.println("Thread 2 executed safely");
					}
				}
			});

			t1.start();
			t2.start();
		}
	}
	
	Solution 2: Using ReentrantLock with tryLock()
	✅ Prevent Deadlock by timeout
	
	import java.util.concurrent.locks.Lock;
	import java.util.concurrent.locks.ReentrantLock;

	class DeadlockTryLock {

		private static final Lock lock1 = new ReentrantLock();
		private static final Lock lock2 = new ReentrantLock();

		public static void main(String[] args) {

			Thread t1 = new Thread(() -> {
				try {
					if (lock1.tryLock() && lock2.tryLock()) {
						System.out.println("Thread 1 acquired both locks");
					}
				} finally {
					lock1.unlock();
					lock2.unlock();
				}
			});

			Thread t2 = new Thread(() -> {
				try {
					if (lock2.tryLock() && lock1.tryLock()) {
						System.out.println("Thread 2 acquired both locks");
					}
				} finally {
					lock1.unlock();
					lock2.unlock();
				}
			});

			t1.start();
			t2.start();
		}
	}

	🧠 Interview line:

	tryLock() avoids deadlock by failing fast instead of waiting forever.

					}
