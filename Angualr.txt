

👉 ngModule :

In Angular, you should NOT put all components into one single AppModule—especially in real projects.

❌ Why adding everything to AppModule is a bad idea

		If you put all components in one module:
		App becomes hard to maintain
		Lazy loading is impossible
		Reusability becomes messy
		Build size grows
		Interviewers ❌ dislike this
	
Feature Modules (most important)
A Feature Module is an Angular module created to handle one specific feature of the application.
Group related components into feature modules.	
		
app/
 ├── auth/
 │    ├── login.component.ts
 │    ├── register.component.ts
 │    └── auth.module.ts
 ├── dashboard/
 │    ├── dashboard.component.ts
 │    └── dashboard.module.ts
 ├── shared/
 │    └── shared.module.ts
 └── app.module.ts
 
👉 What NOT to do (very important)

	[1] ❌ Do NOT import SharedModule in AppModule and every feature module blindly
	[2] ❌ Do NOT put services in SharedModule
	[3] ❌ Do NOT declare the same component in multiple modules

👉 When to use SharedModule

	Use it ONLY for:
		Reusable components
		Reusable directives
		Reusable pipes
		Common Angular modules (CommonModule, FormsModule)
	
“SharedModule contains reusable UI components, directives, and pipes.
It also re-exports CommonModule and FormsModule so feature modules don’t need to import them again.”


Commonly used Angular modules

	[1] BrowserModule
	Used once in AppModule to run the app in the browser.

	[2] CommonModule
	Provides common directives like ngIf, ngFor, and basic pipes.

	[3] FormsModule
	Used for template-driven forms and ngModel.

	[4] ReactiveFormsModule
	Used for reactive forms with FormGroup and FormControl.

	[5] RouterModule
	Handles routing and navigation between components.

	[6] HttpClientModule
	Used to make HTTP / REST API calls.

👉 Eager Loading (Default)

	What it is
	All modules are loaded at application startup.

			import { UsersModule } from './users/users.module';

			@NgModule({
			  imports: [UsersModule]
			})
			export class AppModule {}

👉 Lazy Loading

	What it is
	Modules are loaded only when required (on route access).

	How it works (Routing)

			const routes: Routes = [
			  {
				path: 'users',
				loadChildren: () =>
				  import('./users/users.module').then(m => m.UsersModule)
			  }
			];
			
			
			
	Lazy Loading vs Eager Loading in Angular
	✅ Eager Loading

	Definition: Modules are loaded at application startup.
	Default behavior in Angular.
	AppModule is always eagerly loaded.
	Any module imported directly inside AppModule is also eagerly loaded.

	✔ What happens?

	All eagerly loaded modules are bundled and downloaded when the app starts.

	Increases initial load time if the app is large.

	@NgModule({
	  imports: [
		BrowserModule,
		UserModule,   // 👈 eagerly loaded
		AdminModule   // 👈 eagerly loaded
	  ]
	})
	export class AppModule {}

	✅ Lazy Loading

	Definition: Modules are loaded only when required (on demand).
	Commonly used for feature modules.
	Implemented using Angular Router.
	Improves performance and reduces initial bundle size.

	✔ What happens?

	The module is downloaded only when the user navigates to its route.

	const routes: Routes = [
	  {
		path: 'admin',
		loadChildren: () =>
		  import('./admin/admin.module').then(m => m.AdminModule)
	  }
	];


	➡️ AdminModule loads only when /admin is visited.

	🔁 Your Statement — Corrected Version

	“Lazy loading means loading feature modules only when required, but AppModule is eager loading and loads all modules at the start.”

	✅ Corrected & precise:

	Lazy loading loads feature modules only when they are needed.
	AppModule is always eagerly loaded, and any module directly imported into AppModule is also eagerly loaded.

👉 Style scoping

Why do we need style scoping in Angular

(Even when we already write CSS in component files?)

	Writing CSS in a component file alone does NOT guarantee isolation.
	By default, CSS is global in the browser. Angular adds style scoping to enforce isolation.
	
	Interview-ready one-line answer
	Even though we write CSS in component files, the browser treats all CSS as global. Angular uses style scoping to isolate component styles and prevent conflicts across the application.
	
🔹 ViewEncapsulation (Short Note)

	ViewEncapsulation in Angular controls how component styles are scoped and applied. By default, Angular uses Emulated encapsulation, which scopes styles to the component by adding unique attributes to HTML and CSS, preventing style conflicts.

Angular provides three types of ViewEncapsulation:

	Emulated (Default):
		Styles are scoped to the component using generated attributes. Works in all browsers and is used in most applications.

	None:
		Styles are not scoped and become global, affecting the entire application. Useful for global themes or layout components but risky if overused.

	ShadowDom:
		Uses the browser’s native Shadow DOM for true style isolation. Best for web components and design systems but has limited styling access from outside.

	In short: ViewEncapsulation ensures component style isolation and helps avoid CSS conflicts in large Angular applications.
	
	
		👉 Style Scoping in Angular (Simple & Interview-Ready)

	Style scoping in Angular means:
	👉 CSS written for one component affects only that component, not the entire application.

	This avoids CSS conflicts and makes components truly reusable.

	🔹 How Angular Achieves Style Scoping

	Angular uses View Encapsulation to scope styles.

	Default behavior:
	@Component({
	  selector: 'app-user',
	  templateUrl: './user.component.html',
	  styleUrls: ['./user.component.css']
	})
	export class UserComponent {}


	➡️ Angular automatically scopes styles to this component.

	Internally, Angular:
	Adds unique attributes to HTML elements
	Rewrites CSS selectors to match only those attributes
	
	Example (conceptual):

	<h1 _ngcontent-c1>Profile</h1>

	h1[_ngcontent-c1] {
	  color: blue;
	}

	🔹 Types of View Encapsulation
	1 ️⃣ Emulated (Default & Most Used) ✅
	encapsulation: ViewEncapsulation.Emulated


	Styles apply only to the component
	Uses attribute selectors internally
	Works in all browsers

	✔ Best for most applications
	
	✅ encapsulation: ViewEncapsulation.Emulated means:

	The styles added in this component will apply ONLY to this component.
	They will not affect:
	Other components
	Parent components
	Child components (outside its template)

	2 ️⃣ None (Global Styles) 🌍
	encapsulation: ViewEncapsulation.None


	Styles behave like normal CSS
	Affects entire application
	No scoping
	❌ Can cause style conflicts

	📌 Used for:

	Global themes

	Design systems

	3 ️⃣ Shadow DOM 🌑
	encapsulation: ViewEncapsulation.ShadowDom


	Uses native browser Shadow DOM
	True isolation
	Styles cannot leak in or out
	⚠️ Limited browser support & harder to style globally

	👉 Small Summary (Beginner → Interview Level)

	[1] Host Element

	Host element is the HTML element on which a component or directive is applied.

	<button appHighlight>Click</button>


	➡ <button> is the host element

	[2] Why Host Element Matters

	Angular:
	• attaches logic to it
	• updates its styles, classes, attributes
	• listens to its events

	Everything happens on the host element.

	[3] ElementRef (Old Way)

	Used to directly access the host DOM element.

	this.el.nativeElement.style.background = 'yellow';


	❌ Not recommended
	❌ Unsafe
	❌ Not Angular-friendly

	[4] @HostBinding (Recommended Way)

	Used to bind properties TO the host element safely.

	@HostBinding('style.backgroundColor')
	bg = 'yellow';


	✔ Safe
	✔ Angular-way
	✔ Auto updates with change detection

	[5] @HostListener

	Used to listen to events FROM the host element.

	@HostListener('click')
	onClick() {
	  console.log('clicked');
	}


	✔ No (click) needed in template
	✔ Keeps logic inside directive/component

	[6] HostBinding + HostListener Together
	@HostBinding('class.active') isActive = false;

	@HostListener('mouseenter')
	onEnter() {
	  this.isActive = true;
	}


	👉 Event happens → variable changes → host updates

	[7] Relationship (Very Important)
	Host Element → exists by HTML
	@HostBinding → modifies host
	@HostListener → listens to host

	🧠 One-Line Memory Cheatsheet

	• Host Element → where Angular attaches
	• @HostBinding → apply TO host
	• @HostListener → listen FROM host
	• ElementRef → avoid if possible

	🎯 Interviewer Tips (Very Important)
	Q1: What is host element?

	✅

	“The host element is the HTML element on which a directive or component is applied.”

	Q2: Why not use ElementRef?

	✅

	“Because it directly accesses DOM and is unsafe. Angular recommends HostBinding or Renderer2.”

	Q3: Difference between HostBinding and HostListener?

	✅

	“HostBinding binds properties to the host element, while HostListener listens to events from the host element.”

	Q4: When do you use HostBinding?

	✅

	“When I need to add or update styles, classes, or attributes on the host element.”

	Q5: When do you use HostListener?

	✅

	“When I want to handle host element events like click, hover, or key press.”

	❌ Common Interview Mistakes

	• Saying HostBinding replaces host element
	• Saying HostListener works on child elements
	• Using ElementRef for styling

	⭐ Final Interview Sentence (Use This)

	“Angular provides HostBinding and HostListener to safely interact with the host element without directly touching the DOM.”

	⭐ host vs @HostListener

		Your code using host 👇

			host: {
			  '(click)': 'onConfirmLeavePage($event)'
			}


		Same thing using @HostListener 👇

			@HostListener('click', ['$event'])
			onConfirmLeavePage(event: MouseEvent) { ... }
			
			
	🎯 Goal of the Example

	👉 When the user hovers over a button:

	Background color should change

	When mouse leaves → color should reset

	Without writing any event or class in HTML

	1 ️⃣ HTML (Very Clean)
	<button appHoverEffect>
	  Submit
	</button>


	✅ No (mouseenter)
	✅ No (mouseleave)
	✅ No classes

	👉 Behavior is fully handled by the directive.

	2 ️⃣ Directive Code (Main Logic)
	import { Directive, HostBinding, HostListener } from '@angular/core';

	@Directive({
	  selector: '[appHoverEffect]'
	})
	export class HoverEffectDirective {

	  // 🔹 Bind style to the HOST element (button)
	  @HostBinding('style.backgroundColor') bgColor = 'blue';

	  // 🔹 Listen to mouse enter on the HOST element
	  @HostListener('mouseenter')
	  onMouseEnter() {
		this.bgColor = 'green';
	  }

	  // 🔹 Listen to mouse leave on the HOST element
	  @HostListener('mouseleave')
	  onMouseLeave() {
		this.bgColor = 'blue';
	  }
	}

	3 ️⃣ What is Happening Internally? 🧠
	🔹 Host Element
	<button appHoverEffect>


	This <button> is the host element

	🔹 @HostBinding
	@HostBinding('style.backgroundColor') bgColor = 'blue';


	👉 Means:

	“Bind bgColor variable to the button’s background color”

	So Angular internally does:

	<button style="background-color: blue;">

	🔹 @HostListener
	@HostListener('mouseenter')


	👉 Means:

	“Listen for mouseenter event on the button itself”

	No need to write:

	<button (mouseenter)="...">

	4️ ⃣ Flow (Very Important for Interviews)

	Button loads → color = blue

	Mouse enters button
	→ onMouseEnter() triggered
	→ color becomes green

	Mouse leaves button
	→ onMouseLeave() triggered
	→ color becomes blue

	5 ️⃣ Why This is Better Than Normal HTML Events?

	❌ Bad Approach:

	<button
	  (mouseenter)="changeColor()"
	  (mouseleave)="resetColor()">


	Problems:

	Logic in template

	Not reusable

	Messy HTML

	✅ Angular Way:

	Behavior inside directive

	Clean HTML

	Reusable anywhere

	🎯 Interview One-Line Explanation

	@HostListener listens to events on the host element, and @HostBinding dynamically updates its properties such as styles or classes.

	🧠 Easy Memory Trick

	HostListener → Listen to host events 🎧

	HostBinding → Bind data to host 🧲
	
	
	Your statement → Interview-ready version ✅
🔥	Host is the element from HTML on which a component or directive is applied.
	HostBinding binds properties like class, style, or attributes of that host element from the component.
	HostListener listens to events on the host element, and when an event happens, it triggers a method.

👉 @Input() and @Output() — Short Notes (with Interview Tips)
🔹 @Input()

	What it is
	Used to receive data from parent to child component.

	Direction
	Parent ➝ Child

	How it works
	Parent binds a value, child receives it as a property.

			<app-child [title]="pageTitle"></app-child>

			@Input() title!: string;


	Key Points

		One-way data binding
		Value comes from parent
		Updates trigger ngOnChanges()

	Interview Tips

		Say “one-way data flow”
		Mention ngOnChanges
		Don’t say child can change parent data ❌

🔹 @Output()

	What it is
	Used to send events or data from child to parent.

	Direction
	Child ➝ Parent

	How it works
	Child emits event, parent listens.

		@Output() notify = new EventEmitter<string>();
		this.notify.emit('Hello');

		<app-child (notify)="onNotify($event)"></app-child>


	Key Points

		Uses EventEmitter
		Parent listens using event binding
		$event holds emitted data

	Interview Tips

		Say “event-based communication”
		Mention EventEmitter
		Don’t say two-way binding ❌

🔹 Quick Comparison
	Feature				@Input()			@Output()
	Direction			Parent → Child		Child → Parent
	Purpose				Pass data			Send events
	Binding type		Property binding	Event binding

👉 ngContent :

	🔹 What is ng-content in Angular?

	👉 ng-content is used to pass HTML content from a parent component into a child component.

	This is called Content Projection.

	It helps with:

	✅ Reusability

	✅ Flexible components

	✅ Clean separation of structure and content

	🧠 Simple Definition (Interview One-liner)

	ng-content allows a parent component to project its HTML content into a child component’s template.

📝 ng-content – Short Notes

	ng-content is used for content projection
	It allows parent HTML to be displayed inside a child component
	Used to create shared / reusable HTML layouts
	Child defines structure, parent provides content
	It passes HTML/template, not data

✅ When to Use ng-content

	Common UI layout needed
	Content changes per component

	Examples:

		Card
		Modal
		Panel
		Layout wrapper

❌ When NOT to Use

	To pass values → use @Input
	To send events → use @Output

🔹 Simple Example
	<!-- child -->
	<div class="card">
	  <ng-content></ng-content>
	</div>

	<!-- parent -->
	<app-card>
	  <p>Any HTML here</p>
	</app-card>

👉 @ViewChild in Angular

	What it is
	@ViewChild allows a component to access an element, directive, or child component from its own template.
	
🔹 Why we use @ViewChild

	Access DOM elements
	Call child component methods
	Read values (input, height, width)
	Control focus or behavior programmatically
	
🔹 Simple Example (HTML Element)

	Template

	<input #nameInput type="text">


	Component

	@ViewChild('nameInput') nameInput!: ElementRef;

	ngAfterViewInit() {
	  console.log(this.nameInput.nativeElement.value);
	}

	🔹 Accessing Child Component
	@ViewChild(ChildComponent) child!: ChildComponent;

	ngAfterViewInit() {
	  this.child.someMethod();
	}
	
❌ Why ngModel is NOT enough

	ngModel ❌ cannot:
	Focus an input
	Scroll to an element
	Read element height / width
	Call a child component method
	Access native DOM APIs

	Example:

	this.username = '';   // works
	this.username.focus(); // ❌ not possible
	
🔹 When @ViewChild is REQUIRED
	
	Focus input
	this.input.nativeElement.focus();

	Call child component method
	this.child.resetForm();

	Read DOM property
	this.input.nativeElement.offsetHeight
	
🔹 Short Summary: ngModel vs @ViewChild & Why @ViewChild for Components

	ngModel is used for two-way data binding. It helps you read and update values from form elements.

	@ViewChild (HTML element) is used when you need direct access to the DOM, such as focusing an input, scrolling, or reading size/position.

	@ViewChild (component) is used to get the child component instance, so the parent can:

	Call child methods

	Read child state

	Control reusable UI components (modal, tabs, timer, form reset)

	@Input() and @Output() are for data and events, but they cannot directly control a child component.
	That’s why @ViewChild exists—for direct, programmatic control when needed.

🔹 Interview Questions (Add at Last)

	Q1. If we already have ngModel for two-way binding, why do we need @ViewChild?
	👉 ngModel handles data binding, but @ViewChild is needed to access and control DOM elements or child components directly (focus, methods, state).

	Q2. Why do we use @ViewChild to access another component?
	👉 To get the child component instance and directly call its methods or control its behavior, which is not possible using only @Input() and @Output().
	
	
	ngModel vs @ViewChild (Clear Comparison)
	Feature						ngModel				@ViewChild
	Access value					✅						✅
	Access DOM element				❌						✅
	Call methods (focus, blur)		❌						✅
	Access validation state			⚠️ Limited				✅
	Access child component			❌						✅

👉 ngModel : Summary: How ngModel works

	ngModel is a template-driven directive for two-way data binding.
	Angular converts [(ngModel)] into property + event binding.
	It creates an internal FormControl automatically.
	Uses ControlValueAccessor to connect HTML input with Angular.
	Syncs data in both directions:
	Model → View using writeValue()
	View → Model using ngModelChange
	Tracks state: value, valid/invalid, touched, dirty.
	Requires FormsModule to work
	
	"ngModel works by creating an internal FormControl and using ControlValueAccessor to synchronize data between the component and the DOM through two-way binding."
	
Important internal facts (interview gold)

	[1] ngModel creates FormControl internally
	[2] It works via ControlValueAccessor pattern
	[3] Two-way binding is syntactic sugar, not magic
	[4] Change detection syncs model ↔ view
	[5] Template-driven forms are directive-driven
	
	ngModel = FormControl + ControlValueAccessor + Change Detection
	
	
😄	ngModel vs [(ngModel)]

	1. ngModel (one-way binding) :
	
			<input ngModel />
		
		What it does:

			Creates a FormControl
			Tracks value + state (valid, touched, dirty)
			Does NOT update the component variable automatically

		Use case:

			When you only want form control behavior
			Validation, tracking status, using #ref="ngModel"

		Example:

			<input name="email" ngModel #email="ngModel" />

			email.valid
			email.touched

		📌 Interview line

			ngModel alone provides form control and validation, but not two-way data binding.
			
	2. [(ngModel)] (two-way binding 🍌 banana in a box)
	
				<input [(ngModel)]="username" />
				
			What it does:
				Combines:
				[ngModel] → from component to template
				(ngModelChange) → from template to component

			Keeps template and component in sync

			Example:

				username = '';
				<input [(ngModel)]="username" />
				Typing in input updates username automatically.

			📌 Interview line

				[(ngModel)] enables two-way data binding between template and component.
				
🔥 One-Line Interview Answer (Memorize This 🔥 )

	ngModel is used for form control and validation, while [(ngModel)] provides two-way data binding by synchronizing the value between the template and the component.
	
	
😎 Bonus (Smart Candidate Answer 😎)

	In modern Angular applications, reactive forms are preferred over ngModel for better scalability and testability.

👉 Computed Signal :

computed (Angular Signals)

	computed creates a derived signal.
	Its value is calculated from other signals.
	It automatically re-runs when dependent signals change.
	It is read-only (you can’t set it directly).
	It is lazy → recalculates only when someone reads it.
	
	eg. count = signal(2);

	doubleCount = computed(() => this.count() * 2);
	( If count() changes → doubleCount() updates automatically. )
	
How it works (internally)

	Tracks which signals are read inside it
	Subscribes to those signals
	Recomputes only when needed
	Caches the last value

👉 Directives: 

	What are Directives?

	Component = directive + template

📌PIPES :

	Pipes are used to transform data in the template (HTML) before displaying it to the user.
	They do not change the original data, only the view output.
	
📌 Why Pipes are used

	Format dates, currency, text
	Filter or sort data
	Keep HTML clean
	Avoid writing logic in templates
	
🔧 Custom Pipe (Very Important for Interviews)
	
	import { Pipe, PipeTransform } from '@angular/core';
	@Pipe({
	  name: 'shorten'
	})
	export class ShortenPipe implements PipeTransform {
	  transform(value: string, limit: number) {
		return value.length > limit
		  ? value.substring(0, limit) + '...'
		  : value;
	  }
	}
	
	HTML :
	{{ description | shorten:10 }}

⚡ Pure vs Impure Pipes

🔑 constructor() vs inject()
	constructor() = traditional & most common
	inject() = modern, function-based & flexibl

	“constructor() is preferred for components and services; inject() is useful in functional scenarios.”

🔄 Change Detection in Angular

	Change Detection is the process by which Angular checks whether component data has changed and updates the DOM accordingly.

🧠 Simple Meaning

	Data changes → Angular detects it → UI updates automatically
	
🔁 How Change Detection Works (Step-by-Step)
	User Event / Async Task
			↓
	Zone.js notifies Angular
			↓
	Angular runs Change Detection
			↓
	Checks component bindings
			↓
	Updates DOM if needed
	
🌳 Change Detection Tree

	Angular starts from root component

	Goes top → down through all child components

	This process is called a Change Detection Cycle

		AppComponent
		   ↓
		HeaderComponent
		   ↓
		DashboardComponent
		   ↓
		ChildComponent

🔔 What Triggers Change Detection?
	+---------------------------+----------------------------------+
	| Trigger                   | Example                          |
	+---------------------------+----------------------------------+
	| Browser events            | click, keyup, scroll             |
	| HTTP calls                | API response                     |
	| setTimeout / setInterval  | async operations                 |
	| Promise / Observable      | async pipe, subscribe            |
	| @Input() value change     | Parent → child data change       |
	+---------------------------+----------------------------------+
	(All handled using Zone.js)
	
🧩 What Angular Checks During CD?

	Angular checks:

		Property bindings → {{ value }}

		Attribute bindings → [disabled]

		Structural directives → *ngIf, *ngFor

	🚫 Angular does NOT call methods automatically
	⚠️ But functions inside templates ARE executed every cycle

		{{ getName() }}   ❌ (called many times)
		{{ name }}        ✅ (recommended)


⚙️ Change Detection Strategies
	[1] Default Strategy (default)
	@Component({
	  changeDetection: ChangeDetectionStrategy.Default
	})

	✔ Runs on every change detection cycle
	✔ Checks whole subtree

[2] OnPush Strategy (Important for Interviews)
	@Component({
	  changeDetection: ChangeDetectionStrategy.OnPush
	})

	Runs only when:

	@Input() reference changes
	Event happens inside component
	Observable emits (async pipe)
	markForCheck() is called
	
	✔ Better performance
	✔ Used in large applications
	
🧪 Manual Change Detection (Advanced)
	constructor(private cdr: ChangeDetectorRef) {}

	this.cdr.detectChanges();   // force check
	this.cdr.markForCheck();    // mark for OnPush
	
⚡ Performance Best Practices
	+---------------------------+-------------------------------+
	| Tip                       | Why                           |
	+---------------------------+-------------------------------+
	| Use OnPush                | Reduces checks                |
	| Avoid functions in HTML   | Prevents repeated execution   |
	| Use async pipe            | Auto subscribe + efficient    |
	| Immutable data            | Works well with OnPush        |
	+---------------------------+-------------------------------+

⚡ so while change detction it go through all the compoennets

	Short answer ✅
	Yes — by default, during change detection Angular goes through all components from the root to the leaves.
	
		Any event happens
		  ↓
	Angular starts from AppComponent
		  ↓
	Checks every child component
		  ↓
	Checks their children
		  ↓
	Updates DOM where bindings changed
	
	✔ Even if only one value changed, Angular checks the whole component tree
	
Very common interview trap ❗

	Wrong statement ❌

		“Angular re-renders all components every time”

	Correct statement ✅

		“Angular checks all components, but updates the DOM only where data changes.”
		
30-second interview answer (memorize this)

	“In Default change detection, Angular traverses the entire component tree from root to leaf and checks bindings. It does not re-render everything; it only updates the DOM where values actually change. With OnPush, unchanged subtrees are skipped.”
	
One-line summary 🧾

	Default CD → all components are checked
	OnPush → only affected components are checked

🔄 Async Pipe in Angular

The async pipe is used to subscribe to an Observable or Promise in the template, get its latest value, and automatically unsubscribe when the component is destroyed.

Why do we need async pipe?

		❌ Without async pipe (manual subscription)
		userName!: string;

		ngOnInit() {
		  this.userService.user$.subscribe(name => {
			this.userName = name;
		  });
		}
		
		Must remember to unsubscribe
		More code
		Risk of memory leaks
		
		✅ With async pipe
		<p>{{ userService.user$ | async }}</p>


		That’s it.
		No subscribe(), no unsubscribe().
		
How async pipe works (simple flow)

		Subscribes automatically when template loads
		Listens for new values
		Updates the UI automatically
		Unsubscribes when component is destroyed	


Service
		private nameSubject = new BehaviorSubject<string>('Guest');
		name$ = nameSubject.asObservable();

		setName(name: string) {
		  this.nameSubject.next(name);
		}		
		
Component (HTML only)
		<h2>Welcome {{ name$ | async }}</h2>


		Or directly:

		<h2>Welcome {{ userService.name$ | async }}</h2>
		
Common mistakes 🚨

		❌ Using subscribe() in component + async pipe together
		❌ Forgetting async pipe and manually unsubscribing
		❌ Using async pipe inside .ts file (it’s template-only)
	
Async pipe with HTTP call
		users$ = this.http.get<User[]>('/api/users');

		<ul>
		  <li *ngFor="let user of users$ | async">
			{{ user.name }}

Subject and BehaviorSubject :

✔ When one service changes a value and other components need to react to that change,
	we create a BehaviorSubject in the service, emit new values, and subscribe in the components by injecting that service.
	
Interview-ready explanation 🎯

	“We use a BehaviorSubject in a shared service to maintain state. The service emits updates using next(), and components subscribe to the exposed observable to react to changes.”
		
	
Service (single source of truth)

		import { BehaviorSubject } from 'rxjs';

		@Injectable({ providedIn: 'root' })
		export class UserStateService {

		  private userSubject = new BehaviorSubject<string | null>(null);

		  user$ = this.userSubject.asObservable(); // expose as observable

		  setUser(user: string) {
			this.userSubject.next(user); // emit value
		  }
		}

Component A (changes the value)

		this.userStateService.setUser('Girish');

Component B (reacts to change)
	
		this.userStateService.user$.subscribe(user => {
		  console.log(user);
		});


		Component A
		   |
		   |  (calls method)
		   v
		Shared Service
		   |
		   |  (BehaviorSubject emits)
		   v
		Component B
		
		✔ Components never talk directly
		✔ Service is the middleman / single source of truth



Subject (RxJS)

	👉 What is Subject?

	👉 A Subject is an RxJS object that can:
		send data (using next())
		receive data (using subscribe())

	It does not store any value.
	It only sends data to subscribers who are listening at that moment.
	
	👉Important points about Subject

	No initial value
	Does not remember old values
	Late subscribers miss previous values
	Used mainly for events
	One value can be sent to many subscribers
	
	
	import { Subject } from 'rxjs';

	const subject = new Subject<number>();

	subject.subscribe(v => console.log('A:', v));
	subject.next(1);

	subject.subscribe(v => console.log('B:', v));
	subject.next(2);
	
	A: 1
	A: 2
	B: 2
	
	
BehaviorSubject (RxJS)

	What is BehaviorSubject?

	A BehaviorSubject is a Subject that:
	always has a value
	remembers the latest value
	sends the latest value to new subscribers
	It is mainly used for state management.
	
	Important points about BehaviorSubject

	Needs an initial value
	Stores the latest value
	New subscribers immediately receive the last value
	Every new value overrides the previous one


	import { BehaviorSubject } from 'rxjs';

	const bs = new BehaviorSubject<number>(0);

	bs.subscribe(v => console.log('A:', v));
	bs.next(1);

	bs.subscribe(v => console.log('B:', v));
	bs.next(2);


	A: 0
	A: 1
	B: 1
	A: 2
	B: 2


🔥 Input and Output Vs Subject and behaviorSubject

	1. @Input() / @Output() – Parent ↔ Child only
		ParentComponent
		   |
		   v
		ChildComponent

	
	2. Subject / BehaviorSubject – Unrelated components
		Component A → Service → Component B


🚨 Comparison table (remember this)

	Scenario							Use
	----------------------------------------------------
	Parent → Child						@Input
	Child → Parent						@Output
	Sibling components					Subject
	Components on different routes		Subject
	Shared state						BehaviorSubject

🔐 What are Route Guards?

	Route Guards decide whether a route is allowed or not.
	They run BEFORE a route is activated, loaded, or exited.
	Think of them as security checkpoints for routes.
	
	Why do we need Route Guards?

	Without guards:

	Anyone can access /admin by typing URL ❌
	Sensitive pages exposed ❌

	With guards:

	Auth check ✅
	Role check ✅
	Prevent data loss ✅
	
	1️. CanActivate (Most used 🔥)
	
			Purpose

			✔️ Controls access to a route

			Use case

			Authentication
			Authorization
			
			@Injectable({ providedIn: 'root' })
			export class AuthGuard implements CanActivate {

			  constructor(private auth: AuthService, private router: Router) {}

			  canActivate(): boolean {
				if (this.auth.isLoggedIn()) {
				  return true;
				}
				this.router.navigate(['/login']);
				return false;
			  }
			}

			{ path: 'admin', component: AdminComponent, canActivate: [AuthGuard] }


	2️. CanActivateChild
			Purpose
			✔️ Protects child routes
			
			{
			  path: 'dashboard',
			  component: DashboardComponent,
			  canActivateChild: [AuthGuard],
			  children: [
				{ path: 'profile', component: ProfileComponent },
				{ path: 'settings', component: SettingsComponent }
			  ]
			}

	3. CanDeactivate : ✔️ Prevent user from leaving a page
	4. Resolve : ✔️ Load data before route loads
	5. CanLoad : ✔️ Prevent loading of lazy modules
	
	
Guards can return:

	boolean
	Observable<boolean>
	Promise<boolean>
	UrlTree

Important Interview Points ⚠️

	Guards run before component creation
	Guards DO NOT replace backend security
	Always secure APIs too
	UI guards = UX + basic protection

Q. What is the difference between pure and impure pipes in Angular?
	
	Pure Pipe

		Default in Angular
		Executes only when input reference changes
		Works with immutable data changes
		Faster and better performance
		Does NOT run on internal mutations (push, sort)

	Impure Pipe

		Executes on every change detection
		Detects internal changes in array/object
		Slower (performance expensive)
		Must be explicitly set: pure: false

Q. What is the difference between template-driven and reactive forms?
	Ans. Template driven forms are based on directives while reactive forms are based on reactive programming.
	Template driven forms are easier to use and require less code.
	Reactive forms are more flexible and allow for more complex validation.
	Template driven forms are suitable for simple forms while reactive forms are better for complex forms.
	Template driven forms use two-way data binding while reactive forms use observable streams.
	Template driven forms are synchronous while reactive forms are asynchronous.

Q. How can a component be loaded only after three specific services have loaded?

	In Angular, this is achieved using a Route Resolver or by combining multiple observables and waiting for all of them to complete.
	
	✅ Best & Interview-Preferred Approach: Route Resolver

	A Resolver ensures that required data is loaded before the component is activated.
	
	Step 1: Create Resolver
	
		@Injectable({ providedIn: 'root' })
		export class DataResolver implements Resolve<any> {

		  constructor(
			private service1: Service1,
			private service2: Service2,
			private service3: Service3
		  ) {}

		  resolve() {
			return forkJoin({
			  data1: this.service1.getData(),
			  data2: this.service2.getData(),
			  data3: this.service3.getData()
			});
		  }
		}


	Step 2: Use Resolver in Route
	
		{
		  path: 'dashboard',
		  component: DashboardComponent,
		  resolve: {
			preloadData: DataResolver
		  }
		}

	Step 3: Access Data in Component
	
	ngOnInit() {
	  this.route.data.subscribe(data => {
		this.allData = data['preloadData'];
	  });
	}
	
	✔️ Component loads only after all 3 services complete
